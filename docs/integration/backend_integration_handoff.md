# 1. Executive Summary

Super-7 asynchronously analyses a backend-owned football video. The backend stores the video and later persists the callback result; Super-7 queues work, runs the analysis pipeline, and delivers the callback. It has no backend database client. Evidence: `src/main.py:create_app`, `pyproject.toml`.

```text
Backend shared storage -> POST /analyze -> 202 -> FIFO queue -> one worker -> callback -> backend persistence
```

Evidence: `src/api/routes.py:create_router`, `src/services/analysis_queue.py:AnalysisWorker`.

# 2. Responsibility Boundaries

## Backend owns

Authentication, users, database, video persistence, `videoId`/`playerId`, callback endpoint, and AI-result persistence are backend responsibilities; none is implemented by Super-7.

## Super-7 owns

Super-7 owns video analysis, queueing, model execution, tracking, event detection, scoring, Public Rating V2 projection, and callback delivery. It does not own authentication, database access, backend filesystem layout, or durable job storage. Evidence: `src/main.py:create_app`, `src/api/public_rating_mapper.py:public_rating_v2`.

# 3. POST /analyze Contract

`POST /analyze` accepts an `application/json` Pydantic body. All fields are required, unknown fields are forbidden, and input uses camelCase aliases. Evidence: `src/schemas/analysis.py:AnalyzeRequest`.

| Field | Type | Validation / use | Returned later |
|---|---|---|---|
| `videoId` | string | No non-empty, format, or uniqueness constraint. Propagated. | Callback `video_id`. |
| `playerId` | string | No non-empty, format, or uniqueness constraint. Propagated. | Callback `player_id`. |
| `videoUrl` | string | A relative filename, not a downloaded URL. Must be safe and use `.mp4`, `.mov`, `.mkv`, or `.avi`. | Resolved by worker; not echoed. |
| `callbackUrl` | `HttpUrl` | HTTP(S), host required, resolution only to global/public IPs. | Used as destination; not echoed. |

```json
{"videoId":"video-123","playerId":"player-456","videoUrl":"test-video.mp4","callbackUrl":"https://backend.example.com/api/video-analysis/webhook"}
```

# 4. Immediate 202 Response

After validation and queue admission, HTTP 202 is returned:

```json
{"analysisId":"<uuid4>","videoId":"video-123","playerId":"player-456","status":"queued"}
```

`analysisId` is generated by Super-7. **202 means accepted/queued, not completed.** File existence is not checked until the worker starts. Evidence: `src/api/routes.py:create_router`, `src/schemas/analysis.py:AnalyzeQueuedResponse`.

# 5. Complete Request Lifecycle

Backend request → Pydantic/reference/callback validation → `AnalysisJob` admission (`QUEUED`) → 202 → worker dequeues (`RUNNING`) → file resolution and analysis lifecycle → callback attempt → terminal state. Invalid request/reference/callback is 422; a full queue is 503; a missing file after 202 produces a later failed callback attempt. Evidence: `src/api/routes.py:create_router`, `create_analysis_job_processor`, `src/services/analysis_queue.py`.

# 6. Shared Video Storage Contract

`VIDEO_STORAGE_ROOT` defaults to `/videos`; Compose mounts `/data/videos:/videos:ro`. Example: host `/data/videos/test-video.mp4`, container `/videos/test-video.mp4`, request `"videoUrl":"test-video.mp4"`. Evidence: `src/core/config.py:Settings`, `docker-compose.yml`.

`VideoPathResolver` requires existing readable/searchable root and existing regular readable file. It rejects empty/padded names, absolute POSIX/Windows paths, separators, traversal, unsupported extensions, and symlinks escaping the root. The backend must never send its absolute filesystem path. Evidence: `src/services/video_path_resolver.py:VideoPathResolver`, `tests/test_video_path_resolver.py`.

# 7. Queue Semantics

The queue is a bounded process-local FIFO `asyncio.Queue`; one `AnalysisWorker` consumes it. `MAX_QUEUED_ANALYSES` defaults to 10. `DEFAULT_MAX_ACTIVE_ANALYSES` is 1, so one analysis runs at once. A full/stopped queue returns HTTP 503 and rejected jobs are not callback-delivered. Jobs store only identifiers, reference, callback URL, and timestamp—not video bytes. Queue state is non-durable. Evidence: `src/services/analysis_queue.py`, `src/config/analysis.py`, `src/core/config.py`, `tests/test_analysis_queue.py`.

# 8. Job States

Actual states are `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED`, `CANCELLED`; no external job-status endpoint exists. Normal flow is `QUEUED → RUNNING → COMPLETED`; processing error yields `FAILED`; cancellation/shutdown yields `CANCELLED`. Evidence: `src/services/analysis_queue.py:AnalysisJobState`.

# 9. Callback Contract

Super-7 POSTs JSON to supplied `callbackUrl`, sending `Content-Type` and `Accept` `application/json`. A 2xx response is successful. Each attempt uses `CALLBACK_TIMEOUT_SECONDS` (default 10); there are at most four attempts: initial plus 1-, 2-, and 4-second backoffs. Evidence: `src/services/callback_service.py:CallbackService`, `src/core/config.py:Settings`.

Actual callback fields are snake_case:

```json
{"request_id":"<analysisId>","video_id":"video-123","player_id":"player-456","status":"completed","summary":{},"ratings":{},"events":{},"error":null}
```

Successful data is Public Rating V2 `summary`, `ratings`, and `events`. Non-completed analysis uses its result status and `{}` for those maps. Processing failure uses `status:"failed"`, empty maps, and `error:{"code":"<exception class>","message":"Analysis could not be completed."}`. Evidence: `src/services/callback_service.py:CallbackPayload`, `src/api/routes.py:_callback_payload`, `create_analysis_job_processor`.

# 10. Callback Delivery vs Analysis Result

Pipeline success plus exhausted callback delivery returns internal `COMPLETED` and logs `analysis_callback_failed`. Pipeline/file/result failure attempts a sanitized failed callback and returns `FAILED`. The backend should retain `analysisId` as pending and reconcile/resubmit when callback is absent; Super-7 has no delivery-status/replay endpoint. Evidence: `src/api/routes.py:create_analysis_job_processor`.

# 11. Callback Security Rules

Only HTTP/HTTPS are accepted. Before admission and delivery the hostname is resolved; every address must be global, so localhost, loopback, private, link-local, or mixed answers are rejected. Redirects are refused. Evidence: `src/services/callback_service.py:CallbackService`, `_RejectRedirects`, `tests/test_callback_service.py`.

`http://backend-mock:8080/...` may resolve to a private Docker address and be rejected. Production callbacks require a reachable HTTP(S) ingress resolving only to public/global IPs.

# 12. Public Rating V2

Full Public Rating V2 contains `request_id`, `analysis`, `metadata`, `video`, `player`, `ratings`, `overall`, `summary`, `quality`, `events`, `limitations`, `warnings`, and `versions`; its failure form contains `request_id`, `analysis`, `metadata`, `reason`, `reason_code`, `warnings`, and `retryable`. Evidence: `src/schemas/public_rating_v2.py`, `src/api/public_rating_mapper.py:public_rating_v2`.

Critical: callback forwards only `summary`, `ratings`, and `events`, not the full V2 document. Numeric zero is zero; null means unavailable. `insufficient_evidence` and `unsupported` are not zero; `ambiguous_target` is a non-completed analysis status, and events can be `ambiguous`/`unresolved_conflict`.

# 13. Failure Matrix

| Condition | Behavior | Accepted | Callback | Backend action |
|---|---|---:|---:|---|
| Malformed/missing/extra field | 422 | No | No | Correct request. |
| Invalid callback/reference/extension | 422 | No | No | Correct URL/filename. |
| Missing file after admission | 202 then failed callback attempt | Yes | Attempted | Restore file and deliberately resubmit. |
| Queue full | 503 | No | No | Back off/retry submission. |
| Analysis error | 202 then failed callback attempt | Yes | Attempted | Persist error; decide retry. |
| Cancellation/deadline | No final HTTP change; `CANCELLED` | Yes | Not in cancellation path | Treat as unresolved/resubmit. |
| Callback timeout/non-2xx | 202 already returned; four delivery attempts | Yes | Attempted | Reconcile pending work. |
| Shutdown/restart | waiting jobs cancelled/lost | Previously | Not guaranteed | Reconcile/resubmit. |

Evidence: `src/api/routes.py`, `src/services/analysis_queue.py`, `src/api/request_lifecycle.py`, `src/services/callback_service.py`.

# 14. Idempotency and Duplicate Submission

`videoId` is not an idempotency key. Queue state is keyed by generated `analysis_id`; duplicate submissions are not deduplicated and can run/callback twice. Backend webhook persistence and submission policy must be idempotent. Evidence: `AnalysisJob.create`, `AnalysisQueue.submit`, `create_router`.

# 15. Restart and Durability Semantics

On shutdown, queue admission stops and waiting jobs are drained to `CANCELLED`; lifecycle asks active work to cancel cooperatively; worker is stopped. No durable queue, recovery, outbox, or automatic resumption exists. Backend must retain pending records after 202 and reconcile/re-submit. Evidence: `src/main.py:create_app` lifespan, `AnalysisQueue.stop_accepting`, `RequestLifecycle.shutdown`.

# 16. Timeouts and Deadlines

`REQUEST_DEADLINE_SECONDS` defaults to 900 and starts when worker execution enters `RequestLifecycle.execute_with_artifacts`, not while queued. Cancellation is cooperative at `CancellationChecker` stage boundaries. Inference: native YOLO/OpenCV work can continue until such a boundary because synchronous work runs in a thread; exact interruption latency is not verifiable from the repository. Callback timeout is separate, default 10 seconds per attempt. Evidence: `src/api/request_lifecycle.py`, `src/concurrency/cancellation.py`, `src/concurrency/executor.py`.

# 17. Health and Readiness Endpoints

`GET /health/live` checks startup/detector/configuration flags. `GET /health/ready` checks admission, queue capacity, worker, lifecycle, artifacts, model flag, temporary directory, and storage existence/readability/accessibility/read-only state. `GET /health` combines both. Each returns 200 only when its checks are true, otherwise 503. A busy worker remains ready while queue capacity remains. Evidence: `src/api/health.py:create_health_router`.

The model readiness item is an app-state flag set by `src/main.py:create_app`; model-load probing by readiness is not verifiable from the repository.

# 18. Docker and Networking Requirements

Production Compose exposes `8000:8000`, mounts `./models:/models:ro` and `/data/videos:/videos:ro`, and reads `.env`; Uvicorn binds `0.0.0.0:8000`. Evidence: `docker-compose.yml`, `Dockerfile`. `docker-compose.integration.yml` adds `backend-mock` exposed at host 8081 with callback inspection endpoints (`integration/backend_mock/app.py`).

The backend-to-Super-7 production address is deployment-specific; not verifiable from the repository. `localhost` inside a container refers to that container, not automatically to the host/backend.

# 20. Logging and Correlation

`analysis_job_queued` logs `analysis_id`, `video_id`, `player_id`, queue depth; worker logs started and terminal events with `analysis_id`; callback service logs delivery/rejection with `request_id`. Persist immediate `analysisId`: it is callback `request_id` and the primary correlation key. Evidence: `src/api/routes.py`, `src/services/analysis_queue.py`, `src/services/callback_service.py`.

# 21. Backend Integration Checklist

- Confirm readable shared video exists; send only supported relative basename.
- Send exactly four camelCase fields; callback must be public-IP-resolving HTTP(S).
- After 202, persist `analysisId`, mark pending, retain source file, and do not assume completion.
- On callback, match `request_id`, `video_id`, `player_id`; persist payload/error idempotently.

# 22. Example End-to-End Flow

1. Backend writes `/data/videos/test-video.mp4`.
2. It sends `{"videoId":"video-123","playerId":"player-456","videoUrl":"test-video.mp4","callbackUrl":"https://backend.example.com/api/video-analysis/webhook"}`.
3. It records `{"analysisId":"<uuid>","videoId":"video-123","playerId":"player-456","status":"queued"}`.
4. Worker transitions `QUEUED → RUNNING`, resolves `/videos/test-video.mp4`, then POSTs `{"request_id":"<uuid>","video_id":"video-123","player_id":"player-456","status":"completed","summary":{},"ratings":{},"events":{},"error":null}` (real maps depend on result).
5. Backend persists against its IDs and correlation ID.

# 23. Known Limitations

- In-memory non-durable queue and no recovery/outbox.
- One worker and one model-execution boundary.
- Cooperative rather than forced cancellation.
- SSRF callback rules reject private Docker callback hosts.
- No duplicate-submission or multi-process/multi-replica coordination.

# 24. Backend MUST NOT Assume

- 202 means completion or callback delivery.
- Crash/restart preserves queued jobs.
- `videoId` deduplicates work.
- Backend absolute paths, private Docker callback hosts, or container localhost are valid.
- Multiple analyses run in parallel.
- Callback contains the full Public Rating V2 document.

# 26. Final Handoff Summary

Backend must persist a supported video under shared storage, submit the four-field camelCase request, persist returned `analysisId` as pending, provide an idempotent security-compatible callback endpoint, and reconcile missing callbacks after failures/restarts. Correlate callback snake_case `request_id` to `analysisId`; do not rely on 202, `videoId`, callback retries, or Super-7 for idempotency/durability.
